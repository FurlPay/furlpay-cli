MCP tool reference ​

Complete, source-verified inventory of both MCP servers. Audited 2026-11-17 against src/mcp/server.ts (TypeScript execution server) and lib/mcp.js (JavaScript research server). Nothing on this page is aspirational: a tool listed here is registered in the source, and its schema is the registered schema.

Two surfaces, one rule ​

ServerStart withToolsFile
TypeScript execution serverfurlpay mcp --wallet <name>35src/mcp/server.ts
JavaScript research serverfurlpay mcp29lib/mcp.js

A default install cannot move funds on either surface. Every value-moving tool is structurally ABSENT from tools/list until the operator starts the server with --enable-execution AND a configured agent policy exists — execution mode refuses to start (exit 47) without one. Even in execution mode, mutating tools cannot be called directly: they require the two-phase protocol (preview → confirm). This is proven at the process level by test/mcp-hardening.test.js (spawn-level E2E).

Two-phase execution protocol ​

  1. furlpay_preview_execution { tool, args } — sanitizes arguments (control-char/ANSI stripping, length caps), binds them to a one-time executionHash, returns the net effect. Executes nothing.
  2. furlpay_confirm_execution { executionHash } — executes the stored arguments. Single-use, 10-minute TTL, agent-policy gate re-run on the STORED amount (a confirm call can never smuggle a bigger number past the spend caps). Attempts count against the rolling 30/min mutating rate limit even when refused; every call — allowed or refused — appends an audit line (agent, mode, tool, args hash only) to ~/.furlpay/mcp-audit.jsonl.

Direct dispatch of a mutating tool errors with EXECUTION_MODE_REQUIRED (read-only mode) or TWO_PHASE_REQUIRED (execution mode).

Client configuration ​

Claude Desktop / Cursor (claude_desktop_config.json):

json
{
  "mcpServers": {
    "furlpay-execution": {
      "command": "furlpay",
      "args": ["mcp", "--wallet", "agent-alpha"]
    }
  }
}

Read-only-only setups (research assistants, CI inspection) simply omit the wallet: plain furlpay mcp or furlpay mcp --wallet <name> without --enable-execution can quote, inspect and analyze, but never transact.

Agent rules (load-bearing):

  • Read-only by default; never assume execution permissions exist.
  • Never invent payment completion — a preview is not a settlement, a SIMULATED label is not a transaction.
  • Never bypass Agent Trust: the policy gate runs before signing, on stored amounts, under an OS file lock.
  • Never expose credentials; keys arrive via environment/stdin, never argv.
  • Never retry a value-moving operation without respecting idempotency and the transaction status the ledger reports.
