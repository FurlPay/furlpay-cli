Architecture ​

All diagrams describe the actual source implementation (audited 2026-11-17). Module paths are clickable truth: if a box names src/..., that file exists and behaves as drawn.

1. Entry point & dispatcher ​

bin/furlpay.js routes by command; the TS execution surface is lazy-loaded from dist/ only for the commands that need it.

mermaid
flowchart TD
    argv["furlpay <command> …"] --> BIN["bin/furlpay.js<br/>(JS dispatcher, parseFlags)"]
    BIN -->|hyperliquid, trade, escrow,<br/>finance, oracle, solana, wallet…| TS["dist/cli.js<br/>(FurlPayStellarCli, src/cli.ts)"]
    BIN -->|pay, send, balance, travel,<br/>card, invest, dashboard…| JS["lib/commands.js<br/>(hosted-app surface)"]
    BIN -->|mcp without --wallet| JMCP["lib/mcp.js<br/>(research server, 29 tools)"]
    BIN -->|mcp --wallet X| TMCP["src/mcp/server.ts<br/>(execution server, 35 tools)"]
    BIN -->|microstructure, algo, fork,<br/>short, live| LIBS["lib/ engines<br/>(offline analysis / live feed)"]
    BIN -->|update, doctor, completion,<br/>docs| MISC["lib/update, doctor, completion"]

Nothing signs inside the hosted-API plane; chain signatures are produced locally from the keystore or hardware and only relayed where a platform feature does so explicitly.

8. Two-plane honesty model ​

Every surface carries a runtime label backed by the Honesty Matrix: LIVE (real network, real signatures where applicable), LOCAL, SIMULATED, IMPLEMENTED (offline/stub), BLOCKED, NOT IMPLEMENTED. The label is data on the result object, not prose — tests pin the labels, and the CLI prints them alongside every result.
