Environment Variables ​

The exhaustive reference. Audited 2026-11-17 by grepping every environment access across src/, lib/, bin/ and scripts/, then cross-checked against .env.example — if a variable is listed here, the source reads it; the config-file equivalent (config.toml network profiles) is covered in Configuration & Diagnostics.

Secrets live in environment variables or stdin — never as CLI arguments (argv is visible in process listings and shell history). Variables without the NEXT_PUBLIC_ style prefix never reach any client bundle; they are read only by the local process.

Setup & precedence ​

Bash / macOS / Linux:

bash
export HYPERLIQUID_PRIVATE_KEY="0x..."   # or an env file you source

Windows PowerShell (current session):

powershell
$env:HYPERLIQUID_PRIVATE_KEY = "0x..."

Persisted per-user: setx NAME value (new shells only) or a $PROFILE script. Never place secrets in cloud-synced directories.

Precedence: real environment > .env file (loaded by dotenv from the working directory) > built-in default. A value set in the shell wins over .env.

Rotation: API keys are read at process start — rotating a key takes effect on the next invocation. The keystore master key rotates by re-importing (wallet import). Redaction is property-tested: private keys never appear in errors, toString, JSON, or signature envelopes (test/key-redaction.test.js).

What is deliberately absent ​

  • No FURLPAY_PRIVATE_KEY-style master override for Stellar: Stellar keys live in the encrypted keystore or hardware — never env, never argv.
  • No screening-vendor API keys: OFAC/travel-rule integrations are not implemented in this build and the CLI does not pretend otherwise.
  • No NEXT_PUBLIC_ anything: this is a CLI; secrets never ship to a browser.

Hygiene rules the CLI enforces ​

  • Argv secrets are refused — mnemonics/keys on stdin only (wallet import, login --key).
  • Terminal echo is suppressed for interactive seed-phrase/key input.
  • The session cookie attaches only to furlpay.com over TLS or loopback — pointing --api-base elsewhere sends the request credential-less and says so.
  • Cleartext http:// is refused for remote targets, and refused even on loopback when the environment is live.
  • URLs with embedded credentials (https://user:pass@host) are refused outright.
